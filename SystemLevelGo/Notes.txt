!! Public and private (exported and unexported)
In Go, the iconcepts of public and private visibility are determined by the capitalization of
identifiers rather than using explicit keywords such as public or private found in other
languages. If a name — such as a variable, constant, function, type, or struct field — starts with
an uppercase letter, it is exported, meaning it is publicly accessible from other packages.
Conversely, if the name begins with a lowercase letter, it is unexported and thus private to the
package in which it is defined.

!! Array and slices
Arrays offer predictability and fixed-size precision, while slices provide flexibility and idiomatic power without sacrificing performance.

- Array:
Arrays in Go are fixed-size, indexed collections of elements of the same type. (There is a way to add diff type of values by giving [any] of [interface{}] type to the array)
- var a [3]int, which declares an array of three integers.
- a := [3]int{10, 20, 30} you can also use a composite literal
a[0] refers to the first element, a[1] thesecond, and so on.
Arrays in Go are value types. Therefore, assigning one array to another array copies all its elements.
x Arrays in Go carry their size as part of their type, which means [4]int and [8]int are distinct and incompatible types.

- Slices:
Slices in Go are dynamic, flexible views into arrays. They provide a more convenient and expressive way to work with sequences of data without sacrificing the performance benefits of contiguous memory. A slice does not store data itself, but rather it describes a segment of an underlying array, through three components: a pointer to the first element, a length (the number of accessible elements), and a capacity (the number of elements from the start to the end of the backing array)
- s := []int{1, 2, 3} using a composite literal.
- s := a[1:3] by slicing an array which selects elements from index 1 up to (but not including) index 3.
- Slices grow and shrink through operations such as append()
Their behavior is tightly coupled with the Go memory model and garbage collector and the capacity of a slice is handled by Go.
- make() function we can define the capacity of a slice at creation time using this function, after that, the capacity of the slice doubles each time the length of the slice is about to become bigger than its current capacity.
- numbers := make([]int, 3, 5) creates a slice of integers with a length of 3 and a capacity of 5.


!! Slicing:
In Go, slicing refers to the creation of a new view (slice) into an existing array or slice without copying the underlying data. Both arrays and slices support slicing using the syntax a[start:end]
- arr := [5]int{10, 20, 30, 40, 50}, then sub := arr[1:4] creates a slice containing the elements {20, 30, 40}.
- a[:end] to slice from the beginning, a[start:] to slice until the end, and a[:] to create a slice of the entire array.
x The existing elements are copied into this new array, and the returned slice now references it independently. From this point forward, changes to the new slice do not affect the original array or any other slices based on the old array.
% Run (slicing.go) to check all this.
x The key takeaway is that slices act as views into arrays and share data until an append operation exceeds their capacity.When that happens, Go seamlessly switches the slice to a new, independent array, making further modifications isolated from the original data. This behavior makes slicing both efficient and flexible, as Go minimizes allocations when possible but transparently creates new storage when needed.
x Go passes these values to functions: arrays are passed by value, meaning a full copy is made, while slices are passed by reference, sharing the same underlying array.

!! Data Collections and Functions
Maps let you associate keys with values efficiently, and structs allow you to bundle related fields together into a custom type. Maps serve as the Go built-in associative array type, offering efficient key-value storage with a hash table implementation under the hood. Under the hood, Go implements maps as hash tables, providing average O(1) time (constant) complexity for insertions, deletions, and lookups. Maps are more powerful data structures because they allow you to use indexes of various data types as keys to look up your data if these keys are comparable – if a type cannot be compared using == and !=, you cannot use it as map key.

You can declare a map without initialization, such as 
- var grades map[string]int
which resultsin a nil map that cannot be used until it is initialized.
Alternatively, you can create an empty map with string keys and int values, with make using 
- scores := make(map[string]int)
Another way is to define a map literal with predefined values, as seen with 
- inventory := map[string]int{"apples": 50, "bananas": 30, "oranges": 25}
If you start with a nil map,you must initialize it using make before adding elements.

You can assign values directly using the key, such as 
- grades["Marietta"] = 95 or scores["Team A"] = 150
Updating existing entries works the same way – assigning a new value to an existing key automatically replaces the old one. For instance, 
- grades["Marietta"] = 98 
updates Marietta's grade.

When you access value from a map using a key, Go returns the associated value if it exists. If the key is missing, Go returns the zero value for the value type of the map. For example, if grades["David"] does not exist, the returned value will be 0 since the map stores integers.

- if grade, exists := grades["David"]; exists {
-   fmt.Printf("Marietta exists with grade: %d\n", grade)
- }

The exists Boolean tells you whether the key is present in the map, allowing you to handle missing data gracefully.
Maps in Go allow you to remove entries using the delete() function, which is presented next:
- delete(grades, "Epifanios")
- fmt.Printf("After deleting Epifanios: %v\n", grades)
% Deleting non-existent key is safe (no-op)
- delete(grades, "NonExistent")
% delete(grades, "Epifanios") removes the entry for Epifanios. Importantly, deleting a non-existent key is safe – Go simply ignores the request without throwing an error.

Iteration over maps using the range keyword:
- for name, grade := range grades {
-    fmt.Printf(" %s: %d\n", name, grade)
- }

You can quickly find the number of key-value pairs in a map using the built-in len() function. So, len(grades) returns the number of students currently in the map.
Keys can be strings, integers, Booleans, and more, as long as they are comparable types.

You can nest maps inside other maps to represent hierarchical data:
- studentGrades := map[string]map[string]int{
-   "Alice": {"Math": 95, "Science": 92, "English": 88},
-   "Bob": {"Math": 87, "Science": 90, "English": 85},
- }

Maps in Go are reference types, meaning assigning one map to another does not create a deep copy. Instead, both variables point to the same underlying data. Modifying one map affects the other.
- fmt.Println("10. Maps are Reference Types:")
- original := map[string]int{"a": 1, "b": 2}
- copy := original // This creates a reference, not a copy
- fmt.Printf("Original: %v\n", original)
- fmt.Printf("Copy: %v\n", copy)
- copy["c"] = 3 // Modifying copy affects original
- fmt.Printf("After modifying copy:\n")
- fmt.Printf("Original: %v\n", original)
- fmt.Printf("Copy: %v\n", copy)
- fmt.Println()

x The BankAccount struct ishowcases the simple but effective approach of Go to access control, where field names beginning with uppercase letters (AccountNumber) are exported (public) and accessible from other packages, while field names beginning with lowercase letters (balance and ownerName) are unexported (private) and only accessible within the same package. ~ The User struct showcases how struct tags, which are string literals enclosed in backticks following field declarations, provide a declarative way to specify how fields should be handled by different systems without cluttering the struct definition with imperative code. Each field contains multiple tags separated by spaces, with each tag consisting of a key-value pair that instructs specific libraries or frameworks on how to process that field.
- type User struct {
-   ID int `json:"id" db:"user_id" validate:"required"`
-   Username string `json:"username" db:"username" validate:"required,min=3"`
-   Email string `json:"email" db:"email" validate:"required,email"`
-   Password string `json:"-" db:"password_hash"` // "-" excludes from JSON
-   FullName string `json:"full_name,omitempty" db:"name"` // omitempty excludes
-   if empty
- } `json: "user"`
~ The struct tags illustrate various serialization control mechanisms that the encoding/jsonpackage recognizes and respects during marshaling and unmarshaling operations – marshaling is the process of converting a data structure into a format suitable for storage or transmission (such as JSON or bytes) while unmarshaling is the reverse operation. The ID, Username, and Email fields use straightforward mappings that specify the JSON field names, allowing Go conventional PascalCase field names to be converted to more typical snake_case or camelCase JSON representations. The Password field demonstrates data protection using the special json:"-" tag, which completely excludes the field from JSON serialization, ensuring that sensitive information never appears in API responses or log files. The FullName field uses the omitempty directive, which instructs the JSON encoder to exclude the field from output when it contains the zero value for its type, reducing JSON payload size and avoiding unnecessary null fields The db tags specify database column names, allowing the struct to serve as both a Go data model and a database schema representation. The validate tags provide declarative validation rules that validation libraries can process, specifying requirements such as mandatory fields (required), minimum string lengths (min=3), and format validation (email) without requiring separate validation logic.

- The Insert() method appends a new node to the end of the list. It first creates a new node using the given value. If the list is empty (i.e., Head is nil), the new node becomes the head of the list. Otherwise, the method traverses the list by iterating through each node until it reaches the last node — identified when current.Next is nil. At that point, it links the new node by setting the Next field of the last node to point to it, effectively extending the list.

- The Delete() method removes the first occurrence of a node that matches the given value. It begins by checking if the list is empty; if so, there is nothing to delete. If the head node contains the target value, the head is simply moved to the next node, effectively removing the first element. Otherwise, the function uses two pointers: prev to track the previous node and curr to scan the list. As it traverses, if it finds a node where curr.Value equals the target value, it bypasses the node by setting prev.Next = curr.Next, effectively unlinking it from the list. If the value is not found, the traversal continues until the end.

- The Sort() method arranges the list values in ascending order using the bubble sort algorithm. It starts by checking if the list is empty or contains only one element; in either case, no sorting is needed, so the function returns early. Otherwise, it enters a loop controlled by the swapped flag, which tracks whether any swaps occurred in a pass. Inside the loop, it iterates through the list from the head node, comparing each node's value with the value of the next node. If the current node value is greater than the next node's, the two values are swapped, and the swapped flag is set to true. This process continues until a complete pass occurs with no swaps, meaning the list is fully sorted.

- The Print() method displays the contents of the list in a readable format. It starts from the head node and traverses the list sequentially, printing each node's value followed by " -> " to represent the link to the next node. When it reaches the end of the list (current becomes nil), it prints "nil" to indicate termination.
